01 / The idea

A useful outfit starts with context.

A full wardrobe can still leave you wondering what to wear. WearWise explores how a personal inventory, today’s conditions and an explicit set of rules can work together to make that decision easier.

The project focuses on clothing already owned. Its engineering challenge is to turn ambiguous image descriptions into consistent attributes that a rule engine can actually use.

    03 / The architecture

    Perception first.
    Explicit reasoning next.

    01

    See the garments

    GPT-4o extracts attributes from uploaded images. A second pass with GPT-4o-mini corrects and standardizes the description.

    02

    Give the data a vocabulary

    Eight dictionaries map clothing terms, colors and context attributes to consistent values. Raw, corrected and normalized attributes remain available.

    03

    Build a persistent wardrobe

    MongoDB stores a document for each detected garment, alongside a thumbnail used by the Streamlit interface.

    04

    Derive, filter, rank, assemble

    A forward-chaining loop adds facts until none change. The selector filters candidates, applies heuristic scores and fills the available outfit slots.

    The design decision: use AI to interpret images and keep recommendation rules explicit. It makes individual decisions easier to inspect, while highlighting where vocabulary and rule coverage need improvement.

    04 / The original application

    From upload to recommendation.

    The application exposes the extraction stages and displays the selected garments. The interactive lab above adds an explanation panel so the rule behavior can be explored directly in this portfolio.

    05 / Inside the code

    Follow a garment through the logic.

    Three decisions from the Python implementation I co-developed: normalize the input, derive context facts and score suitable candidates.

    01

    Give different words the same meaning.

    Image extraction can describe the same attribute in different ways. A dictionary maps recognized variants to the vocabulary used by the rules.

    normalizer.py · normalize_valuePYTHON
    ORIGINAL SOURCE EXCERPT
    def normalize_value(value, dictionary):
    "Normalizes an attribute with the corresponding dictionary in normalization"

    if not value:
        return None
    key = value.strip().lower()
    return dictionary.get(key, value)
    1. Return None for an empty value, so the missing attribute stays explicit.
    2. Trim whitespace and lowercase a lookup key before checking the dictionary.
    3. Return the mapped value when present. Unknown terms keep the original input; not every value is guaranteed to be canonical.

    02

    Turn temperature into requirements.

    The inference loop adds facts until no new facts are derived. This excerpt is the temperature branch of that loop.

    forward_chaining.py · forward_chain / temperature branchPYTHON
    ORIGINAL SOURCE EXCERPT
    rules = wardrobe_rules["rules"]
changed = True
while changed:
    changed = False

    # temperature rules
    temp_fact = next((f for f in facts if f.startswith("temperature:")), None)
    if temp_fact:
        temp_val = float(temp_fact.split(":", 1)[1])
        for tr in rules["temperature_rules"]["rules"]:
            if tr["min"] <= temp_val <= tr["max"]:
                band_fact = f"temp_band:{tr['name']}"
                if band_fact not in facts:
                    facts.add(band_fact)
                    changed = True
                for req in tr.get("required", []):
                    rf = f"need:{req}"
                    if rf not in facts:
                        facts.add(rf)
                        changed = True
                for forb in tr.get("forbidden", []):
                    ff = f"forbid:{forb}"
                    if ff not in facts:
                        facts.add(ff)
                        changed = True
                break
    1. Read the temperature fact and find its configured band.
    2. Add the band, requested clothing and exclusions to the fact set.
    3. Mark a change only when a fact is new. Repeating the loop eventually reaches a stable set.
    ILLUSTRATIVE WALKTHROUGH

Matching band: mild (13–18°C)

               need:shirt
               need:thin_sweater
These are requests; the later selector uses the available wardrobe.
    03

    Rank candidates with an explainable score.

    After eligibility checks, the engine rewards occasion and formality matches. Other terms can add color compatibility and preference points.

    forward_chaining.py · calculate_score / occasion & formalityPYTHON
    ORIGINAL SOURCE EXCERPT
    g_occasion = attrs.get("occasion")
user_occasion = next((f.split(":")[1] for f in user_facts if f.startswith("occasion:")), None)
if user_occasion and g_occasion:
    if user_occasion == g_occasion:
        score += 10
    elif attrs.get("garment_type") != "outerwear":
        score -= 5

# formality
if user_formality and attrs.get("formality") == user_formality:
    score += 5
    1. A matching occasion adds 10 points. A mismatch subtracts 5, except for outerwear.
    2. An exact formality match adds another 5 points.
    3. The selector checks the strict pool before the fallback pool; the score is only part of the choice.

    06 / The next iteration

    Make the vocabulary as precise as the rules.

    The main opportunity is consistency: some rule terms differ from normalized garment names. Required items are also filled opportunistically, and fallback choices can relax formality preferences. The demo makes those behaviors visible.

    A next version would unify the vocabulary, validate extracted attributes, improve required-item handling and bring explanations into the original app. The README documents the current behavior and reproducible offline checks.
